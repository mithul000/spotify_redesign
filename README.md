# Spotify Web Player UX Case Study

## Task

Improve the user experience of the existing application: [Spotify Web Player](https://open.spotify.com).

This README presents a simple UX case study process: understand the product, identify usability issues, propose improvements, and define the expected impact.

## Desktop Prototype

Figma design: [Spotify Web Player UX Improvement - Desktop Prototype](https://www.figma.com/proto/2yXdJjF3j38rzPtYQr7Pzj/Spotify-Web-Player-UX-Improvement---Desktop-Prototype?node-id=6-75&t=bulfeCYCSxjJjrUV-0&scaling=scale-down-width&content-scaling=fixed&page-id=6%3A2&starting-point-node-id=6%3A3)

The prototype is designed for desktop only at a 1440 px wide layout. A separate Figma page named **5 Page Desktop Navigation** shows the navigation structure with a maximum of five pages.

## Navigation Structure

The desktop prototype uses a simple 5-page navigation:

1. Home
2. Search
3. Library
4. Queue
5. Profile

This keeps the experience focused and avoids unnecessary navigation complexity.

In the Figma prototype, each sidebar navigation item is connected to its matching desktop page. For example, clicking **Search** opens the Search page, clicking **Library** opens the Library page, and the same behavior is applied for Home, Queue, and Profile.

## Product Overview

Spotify Web Player is a browser-based music and podcast streaming experience. Users can search for songs, albums, playlists, podcasts, artists, and saved content, then play or manage audio directly from the web interface.

## UX Goal

Make Spotify Web Player easier to navigate, faster to use, and more helpful for users who want to find, organize, and continue listening to music with less effort.

## Target Users

- Daily music listeners who use Spotify while studying, working, or relaxing
- Podcast listeners who switch between episodes and playlists
- New users who are learning the Spotify interface
- Returning users who want quick access to recently played content

## Current Experience

Spotify already has a strong visual identity, recognizable navigation, and a large content library. However, users can still face friction when trying to quickly find saved content, understand playback options, or manage recommendations.

## Identified UX Issues

1. Search results can feel crowded

   Users may see songs, artists, playlists, podcasts, and profiles together, which can make it harder to quickly choose the right result.

2. Library organization can be improved

   Saved playlists, albums, podcasts, and liked songs can become difficult to scan when the user has a large library.

3. Recommendation control is limited

   Users may want clearer ways to tell Spotify what they like, dislike, want less of, or want to save for later.

4. Playback queue visibility can be stronger

   The queue is useful, but users may not always notice it or understand what will play next.

5. New user guidance is minimal

   First-time users may need clearer onboarding for search, library, playlist creation, and queue management.

## Proposed UX Improvements

### 1. Cleaner Search Experience

Add clearer filter tabs and stronger visual grouping for:

- Songs
- Artists
- Albums
- Playlists
- Podcasts
- Profiles

This would help users move from search intent to result selection faster.

### 2. Smarter Library Filters

Improve the library with quick filters such as:

- Recently played
- Downloaded or saved
- Created by me
- Podcasts
- Albums
- Mood or genre

This would make large libraries easier to scan and reduce repeated searching.

### 3. Better Recommendation Feedback

Add simple feedback actions near recommendations:

- Like
- Not interested
- Play more like this
- Save for later

This gives users more control over their listening experience and improves trust in recommendations.

### 4. More Visible Queue Preview

Show a compact "Up Next" preview near the player area. Users should be able to quickly see the next track and open the full queue when needed.

This improves confidence and prevents surprise playback changes.

### 5. Simple First-Time User Tips

Add lightweight onboarding tips for new users:

- How to search
- How to create a playlist
- How to save songs
- How to manage the queue

These tips should be dismissible and should not interrupt music playback.

## Improved User Flow

1. User opens Spotify Web Player.
2. User searches for a song, artist, podcast, or playlist.
3. Results are grouped by type with clear filters.
4. User plays content and sees a small "Up Next" preview.
5. User saves content or gives recommendation feedback.
6. User later returns to the library and finds saved content through smart filters.

## Expected Impact

- Faster content discovery
- Reduced confusion in search results
- Easier library management
- Better user control over recommendations
- Improved listening confidence through clearer queue visibility
- Friendlier experience for new users

## Success Metrics

- Reduced time to find and play desired content
- Increased use of library filters
- Increased playlist creation and saved songs
- Reduced skipped recommendations
- Higher user satisfaction during search and playback tasks

## Design Principles

- Keep music as the primary focus
- Reduce visual clutter without removing useful controls
- Make frequent actions easy to reach
- Give users more control over personalization
- Support both new and experienced listeners

## Conclusion

The proposed improvements focus on practical usability gains rather than changing Spotify's core identity. By improving search clarity, library organization, recommendation feedback, queue visibility, and onboarding, Spotify Web Player can offer a smoother and more confident listening experience.
